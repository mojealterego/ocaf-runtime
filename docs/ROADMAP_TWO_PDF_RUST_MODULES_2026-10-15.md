Fragmenty Rust mają charakter prototypowy; część obietnic skuteczności i parametrów ma status **hipotezy wymagającej eksperymentów**.
- Powiązania z historycznymi komponentami 0.43–0.99 stanowią **rozszerzenia** już istniejącej roadmapy, nie alternatywny system, fork ani nowe płatne konto. Nowe numery `1.00–1.14` oznaczają etapy ROADMAPY, nie deklarację wydanej wersji produktu.
- Każdy nowy adapter wymaga: `upstream URL + exact release/commit + license audit + SBOM + capability policy + negative tests + real backend smoke + fail-closed rollback + evidence ID`. Nie można zmieniać statusu `TODO` bez dowodu.
- Przesłane PDF nie dostarczają poświadczeń do rzeczywistej sieci telefonicznej, kont usług TTS/MDM lub hostów GPU. **Nie wpisywać** `PASS` dla DID/eSIM, wykrywania exploitów zero-click, monitoringu Apple dyld, nieosiągniętych GPU/SIP/Matrix ani syntetycznych wyników benchmarków. Nie używać przykładów telefonów jako prawdziwych numerów DID. Wszystkie działania medyczne, MDM, telefoniczne, sieciowe i płatne muszą pozostać jawnie uprawnione.

## Backlog testów bezpieczeństwa i realności z dokumentów

1. **Prototypów Rust z PDF nie wklejać dosłownie.** Skrajnie krótkie przykłady `str::replace` w HTML, fikcyjne numery eSIM/DID, `signature_valid:bool` w SIP i `dyld_pac_integrity_ok` w iOS nie są rzeczywistym API, dowodem bezpieczeństwa ani sprawdzeniem certyfikatów. Najpierw typed API, testy negatywne, upstream i prawdziwa integracja.
2. **Threat Intel**, w tym nazwy exploitów i konkretnych CVE, jest treścią otrzymanego PDF: każdy wniosek o **potwierdzonej** podatności/konkretnej wersji systemu wymaga oddzielnej weryfikacji w niezależnym kanale PSIRT/NVD przed włączeniem detekcji do produkcji. Zachować wyłącznie obronne zakresy, nie implementować RAT/phishing/stealer.
3. **P0 test matrix** dla WASI: rzeczywiste Linux guest `/sbin/init` → interpreter WASI → bounded exit/serial receipt, pinned rootfs/kernel/module; invalid manifest and tampered payload deny, two jailed tenants on actual KVM, independent resource/quota observability, SIGKILL and replay check.
4. **P0 test matrix** dla PG: dwa live kernels połączone bezpośrednio TCP; trzeci świadek quorum, partition/downtime, promotion/fencing including former primary comeback; `pg_stat_wal_receiver` WAL catchup, 30/60/120min metrics.
5. **CI realness metadata**: `kernel_boot_id`, `vm_id`, `cgroup_inode`, `postgres_version`, `wal_lsn`, signed module digest, actual server exit codes, host topology and whether `physical_host_power_loss_tested`. Never equate test of a local process with remote-site disaster.

**Kamienie milowe mogą być rozszerzane bez zmiany kolejności już zatwierdzonych prac.** Rozwój bez osobnych podpisów zewnętrznych został autoryzowany przez operatora; nie zastępuje technicznych dowodów.
