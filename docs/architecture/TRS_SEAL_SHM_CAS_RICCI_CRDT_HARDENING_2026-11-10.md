## Cross-cutting invariants
All operations are tenant-scoped and fail closed. Mutations require authorized capability, immutable audit receipt, bounded resource usage and monotonic revision/epoch. ## H01 — TRS-SEAL key and fencing epoch rotation
**Source reference:** PDF pp. 18–20: `TrsSealEngine`, `AntiReplayWindow`, nonce `sequence[0..8] || epoch_low32[8..12]`.
**Design:** `KeyEpoch { tenant_id, node_id, key_id: u64, fencing_epoch: u64, activated_at_ms: u64, expires_at_ms: u64, key_derivation_salt: [u8;32] }`; `RotationPolicy { max_messages: u64, max_age_ms: u64, overlap_ms: u64 }`. Derive AEAD key with HKDF-SHA256, salt bound to tenant/node and full 64-bit epoch, info `OCAF/TRS-SEAL/v2/AEAD` + key_id. Nonce MUST be unique per key; allocate a persistent 96-bit nonce counter or use per-epoch randomized prefix plus persistent sequence; reject wraparound. The current PDF truncates epoch to u32 in the nonce, so full epoch must be authenticated in AEAD AAD and signed transcript; avoid cross-epoch key/nonce reuse. Rotate key atomically with persistent epoch CAS, then distribute authenticated epoch update. A fencing epoch is an authority/lease term, **not** a wall-clock timer: rotate on leadership change, lease expiry or explicit rekey only after durable quorum/fencing decision; do not let every node independently increment it. Separate crypto key rotation from leadership fencing. During bounded overlap accept prior key for decrypt-only, never for new writes. Replay windows keyed by (tenant, sender, key_id, epoch); commit replay advancement only after signature and AEAD verification. Zeroize retired keys.
**Evidence:** deterministic virtual-clock tests at key expiry, sequence wrap, simultaneous rotations, crash between persist/publish, replay before/after failed authentication, old-leader write after fencing, 2^32 epoch boundary, two-tenant separation. Invariant: `accepted_write => write_epoch == authoritative_epoch && key_id is active && nonce_unused`.

## H02 — event-driven shared memory notification
**Source reference:** PDF pp. 15–17: `ShmHeader`, `ZeroCopyBuffer`.
**Design:** Linux shared memory via `memfd_create` + `mmap(MAP_SHARED)` and eventfd or futex; transport descriptors via authenticated Unix domain socket (SCM_RIGHTS), never serialize process-local pointers. `#[repr(C, align(64))] ShmHeaderV2 { magic:u32, version:u32, capacity:u64, len:AtomicU64, generation:AtomicU64, owner_epoch:AtomicU64, state:AtomicU32, refcount:AtomicU32, digest:[u8;32] }`. Writer reserves exclusive ownership, writes bytes and digest, publishes `state=READY` with Release, increments generation, signals eventfd. Reader waits via epoll/eventfd (or futex wait on generation) and reads with Acquire; verify length <= capacity, epoch and digest. Handle EINTR, EAGAIN, cancellation, timeout, lost wakeups by rechecking generation in a loop. Never return an unguarded `&[u8]` that can outlive mapping or race with writer; return RAII read guard with immutable snapshot lifetime. Handle refcount overflow, allocation failure, close/unmap exactly once. On Android/Linux support futex; on Windows/macOS/iOS use platform-specific mapping and notification backends; no claim that eventfd is portable.
**Evidence:** 1/2/16 producers/readers, forced spurious wakeup, signal-before-wait, process crash, owner-epoch change, payload length 0/max/max+1, checksum mismatch, TSAN/Miri where supported, no polling in idle trace.

## H03 — formal TaskAggregate CAS model
**Source reference:** PDF pp. 3–9: `TaskState`, `transition_cas`, `AuditReceipt`.
**Design:** TLA+ state `[state, revision, lease_epoch, owner, receipt_log]`; actions Validate, Queue, Lease, Start, Verify, Succeed, Fail, Cancel, Expire, Recover and CASConflict. Safety: `revision' = revision + 1` iff accepted transition; rejected transition changes neither aggregate nor receipt log; at most one accepted transition per expected revision; terminal state immutable; Running requires valid lease and current fencing epoch; every accepted transition emits exactly one durable receipt with correct old/new states. Atomicity requires transactional commit of aggregate and outbox/receipt; sign before commit or bind signing to transactionally stored canonical event. The PDF reference mutates `self.state` before building receipt and formats the action using the already mutated state; preserve `old_state` for receipt. Prevent revision overflow with checked_add. Fairness assumptions must be explicit; model checking cannot prove deadlock freedom of unbounded external services.
**Evidence:** TLC/Apalache bounded 2 writers × 3 tasks × 4 epochs, stale CAS, cancellation races, lease expiry, crash before/after commit, injected receipt-signing failure, replayed idempotency key; model trace and invariant report attached to CI artifact.

## H04 — numerically safe Ricci routing
**Source reference:** PDF pp. 20–21: `RoutingGraphEdge`, `RicciFlowOptimizer`.
**Design:** Validate all input f64 with `is_finite()`; require `0 < learning_rate <= 1`, `0 < min_weight <= max_weight`, finite positive distances and nonnegative finite load. Guard every intermediate `W1`, curvature, adjustment, updated weight; if invalid, discard candidate weights and fall back atomically to validated Dijkstra weights. No partial graph mutation. Distinguish the PDF's proxy `distribution_cost / metric_distance` from actual Ollivier-Ricci curvature: true W1 requires defined neighborhood probability measures and optimal transport; do not claim the proxy is mathematically equivalent. Deterministic stable ordering and tie-breaking. Routing heuristic cannot modify authority, fencing or durable transaction log.
**Evidence:** NaN/+Inf/-Inf/±0/subnormal/overflow, disconnected graph, zero distance, very high traffic, 10000 seeded random finite graphs, no negative edge, finite output and deterministic fallback.

## H05 — CRDT safe compaction and garbage collection
**Source reference:** PDF pp. 11–13: `VectorClock`, `CrdtOperation`, `CrdtStateStore`.
**Design:** Track stable causal frontier from acknowledged durable checkpoints of **all current replica members**, with explicit membership epoch and join/leave protocol. GC only operations dominated by stable frontier after snapshot persisted and cryptographically bound to tenant, membership epoch and frontier. Keep tombstones until delete is causally stable; never discard dedup metadata for offline replicas still eligible to reconnect. Late replicas behind compaction frontier must install snapshot and resume from cursor; do not apply their old operations without reconciliation. Bound per-tenant memory/disk, batch compaction, retain checkpoints for crash recovery, use atomic snapshot+frontier commit. The PDF's `seen_operations` set is unbounded and delete handling is incomplete; design requires tombstones, causal metadata and deterministic conflict resolution.
**Evidence:** 3/5/9 replica deterministic network partitions, reorder/duplicate, offline reconnect before/after GC, membership churn, delete resurrection prevention, crash during snapshot, tenant isolation, convergence after heal, memory growth bounded by active causal horizon.
