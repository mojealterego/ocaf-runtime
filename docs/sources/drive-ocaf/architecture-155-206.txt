# Architektura Wykonawcza OCAF-Runtime: Mapa Drogowa (1.55–2.06) oraz Kompletna
Implementacja Systemowa
## Syntetyczna Rekonstrukcja Architektury i Kontekstu Ekosystemu OCAF-Runtime
Repozytorium mojealterego/ocaf-runtime funkcjonuje w ramach spójnego ekosystemu
inżynieryjnego rozwijanego przez Andrzeja Mikulskiego (@mojealterego), obejmującego
pakiety wykonawcze z nadzorem polityk w Nowe-projekty, niskoopóźnieniowy silnik
wyszukiwania i rejestrowania decyzji w języku Rust The-Zero-Latency-Builder-Sprint, bazę
architektury kognitywnej Knowledge-projects, zintegrowaną fabrykę narzędzi MCP
Agent-God-Level-Omega oraz wielowarstwowe środowisko wykonawcze NewGPT
obejmujące warstwy Cognitive Core 2.0 i Nexus 4.0. Ponieważ bezpośrednie zapytania
sieciowe do punktu końcowego API dla ocaf-runtime wskazują na status repozytorium
nieindeksowanego publicznie lub tymczasową niedostępność rozwiązania nazw,
rekonstrukcja specyfikacji technicznej oraz mapy drogowej od punktu 1.55 do 2.06 opiera się
na rygorystycznej syntezie istniejących fundamentów kodu w bliźniaczych repozytoriach
autora oraz formalnej specyfikacji paradygmatu OCAF.
Architektura ocaf-runtime stanowi hybrydowe środowisko wykonawcze łączące trzy
komplementarne paradygmaty inżynierii oprogramowania i systemów rozproszonych.
Pierwszym filarem jest strukturalny model referencyjny Open CASCADE Application
Framework (OCAF), w którym zamiast kruchego dziedziczenia klas obiektowych dane
domenowe, parametry wykonawcze oraz dowody audytowe są agregowane w
hierarchicznym drzewie etykiet (Label) adresowanych za pomocą trwałych kluczy
referencyjnych (Tag, przykładowo 0:1:2:1). Do każdej etykiety dołączane są silnie typowane
atrybuty identyfikowane unikalnym identyfikatorem GUID, co pozwala uniknąć konieczności
modyfikowania formatu zapisu przy rozbudowie struktur aplikacyjnych. Węzły danych w
czasie wykonania (runtime) przyjmują jawnie kontrolowane stany spójności, przechodząc od
stanu odłączonego (Detached), przez stan podłączony niespójny (Attached, bad-formed), aż
do stanu podłączonego i w pełni zainicjalizowanego (Attached, well-formed). Modyfikacje na
tym drzewie podlegają atomowym transakcjom z natywną obsługą wielopoziomowego
cofania i ponawiania operacji (Undo/Redo), natomiast propagacja zmian między zależnymi
węzłami odbywa się poprzez skierowany graf acykliczny mechanizmu funkcyjnego (Function
Mechanism: Arguments, Execute, Results).
Drugim filarem konstrukcyjnym jest kognitywny model analizy kolaboracji obiektowej
(Object-oriented Collaboration Analysis Framework), który w przeciwieństwie do systemów
skupionych wyłącznie na strumieniu komunikatów między agentami umieszcza w centrum
uwagi same obiekty współdzielonego rozwiązania. Każdy artefakt w drzewie stanu niesie
własną historię mutacji, wektor współwłasności poszczególnych aktorów obejmujących ludzi
oraz wyspecjalizowanych agentów AI, zapis przesunięć fokusu (focus shifts) oraz przypisane
operatory kognitywne. Trzeci filar obejmuje nadzór wykonawczy, kontrolę epistemiczną oraz
deterministyczny dziennik zdarzeń (Governed Agentic Runtime), których wzorce
wypracowane w repozytoriach Nowe-projekty, The-Zero-Latency-Builder-Sprint oraz
Knowledge-projects (Iteracja 11) narzucają twardą separację probabilistycznych wyjść
modeli językowych od autorytatywnych mutacji stanu. Każde wywołanie narzędzia
przechodzi przez bramkę polityk (PolicyGate) z ograniczeniem ryzyka, takim jak blokada
zobowiązań zakupowych powyżej poziomu średniego (medium) bez jawnej autoryzacji
człowieka, a następnie podlega zapisowi do trwałego dziennika zdarzeń (ReplayLedger)
oraz weryfikacji w rejestrze twierdzeń (ClaimLedger), który oddziela zweryfikowane fakty
wykonawcze od adapterów w fazie mapy drogowej i hipotez badawczych.

## Etap I (Punkty 1.55–1.60): Fundament Drzewa Referencyjnego OCAF, Transakcyjności i
Bramki Polityk
Pierwszy etap mapy drogowej realizuje przejście od luźno powiązanych struktur danych do
rygorystycznego modelu Application-Document-Attribute znanego z architektury OCAF,
wzbogaconego o deterministyczną kontrolę polityk i niezmienny dziennik audytowy.
Zastosowanie agregacji atrybutów wokół trwałych kluczy referencyjnych (Label) zamiast
dziedziczenia klasowego sprawia, że format persystencji dokumentu pozostaje stabilny
nawet przy dynamicznym rozszerzaniu funkcjonalności systemu w czasie wykonania.
### Punkt 1.55: Hierarchiczny Model Kluczy Referencyjnych (Label/Tag) i Atrybutów GUID
W punkcie 1.55 definiowany jest fundamentalny budulec przestrzeni adresowej ocaf-runtime:
drzewo etykiet (OCAFLabel), w którym korzeń dokumentu posiada zawsze znacznik 0, a
każda etykieta potomna otrzymuje unikalny wśród rodzeństwa znacznik całkowity (Tag),
tworząc trwały adres persystentny w postaci ścieżki 0:1:2:.... Do pojedynczej etykiety można
dołączyć wiele atrybutów (OCAFAttribute), przy czym obowiązuje twardy niezmiennik
strukturalny: na danej etykicie może znajdować się co najwyżej jeden atrybut o określonym
identyfikatorze GUID. Każdy węzeł danych podlega ponadto maszynie stanów walidacji:
Detached (odłączony od bazy dokumentu), AttachedBadFormed (podłączony, lecz
niekompletnie zainicjalizowany) oraz AttachedWellFormed (podłączony i w pełni
zweryfikowany).

```typescript
      if (parent !== null && (!Number.isInteger(tag) || tag <= 0)) {

      const tags: number[] = [];

      while (cursor !== null) {
        tags.unshift(cursor.tag);
        cursor = cursor.parent;
      }
      return tags.join(':');
    }

    public getValidityState(): NodeValidityState {
     if (!this.attached) {
       return 'Detached';
     }
     if (this.attributes.size === 0 && this.children.size === 0 && this.parent !== null) {
       return 'AttachedBadFormed';
     }
     for (const attr of this.attributes.values()) {
       if (!attr.validate()) {
         return 'AttachedBadFormed';
       }
     }
     return 'AttachedWellFormed';
 }

   this.attached = false;

     return existing;

   if (!createIfMissing) {
     return null;

   this.children.set(tag, created);
   return created;

Duplicate GUIDs on the same label are prohibited.`

existing?.clone(), attribute.clone());
   this.attributes.set(attribute.id, attribute.clone());
   this.forgottenAttributes.delete(attribute.id);
 }

     this.assertAttached();

   if (attribute === undefined) {
     this.attributes.delete(guid);

  const result: OCAFLabel[] = [];
  const sortedTags = Array.from(this.children.keys()).sort((a, b) => a - b);
  for (const tag of sortedTags) {
         const child = this.children.get(tag)!;
         result.push(child);
         if (allLevels) {
           result.push(...child.iterateChildren(true));
         }
        }
        return result;

    public resolveByEntry(entry: string, createIfMissing: boolean = false): OCAFLabel | null {
      const parts = entry.split(':').map((p) => Number.parseInt(p, 10));
      if (parts.length === 0 || parts[0] !== 0 || parts.some(Number.isNaN)) {
        throw new Error(`Malformed OCAF label entry address: ${entry}`);
      }
      let root: OCAFLabel = this;
      while (root.parent !== null) {
        root = root.parent;
      }
      let current: OCAFLabel | null = root;
      for (let i = 1; i < parts.length; i++) {
        if (!current) return null;
        current = current.findChild(parts[i], createIfMissing);
      }
      return current;
    }

    private assertAttached(): void {
      if (!this.attached) {
        throw new Error(`Operation rejected: Label ${this.getEntry()} is in Detached state.`);
      }
    }
}
```

### Punkt 1.56: Menedżer Transakcji Dokumentu i Wielopoziomowy Silnik Undo/Redo
Zgodnie ze specyfikacją TDocStd_Document, wsparcie dla uogólnionego mechanizmu
Undo/Redo musi być wbudowane w rdzeń architektury od najwcześniejszego etapu
projektowania. Punkt 1.56 wprowadza klasę OCAFDocument, która przechwytuje każdą
zmianę atrybutu poprzez hak mutacyjny (AttributeMutationHook), buduje atomowe ramki delt
transakcyjnych oraz pozwala na bezstratne wycofywanie (abortCommand, undo) i
ponawianie (redo) zmian na całym drzewie referencyjnym.
```typescript

export interface AttributeDeltaRecord {
  readonly labelEntry: string;
  readonly guid: StandardGUID;
  readonly beforeState: OCAFAttribute | undefined;
  readonly afterState: OCAFAttribute | undefined;
}

export interface TransactionFrame {
  readonly transactionId: number;
  readonly commandName: string;
  readonly timestampMs: number;
  readonly deltas: AttributeDeltaRecord[];
}

export class OCAFDocument implements AttributeMutationHook {
 public readonly root: OCAFLabel;
 private activeTransaction: { id: number; name: string; deltas: AttributeDeltaRecord[] } | null =
null;
 private nextTransactionId: number = 1;
 private readonly undoStack: TransactionFrame[] = [];
 private readonly redoStack: TransactionFrame[] = [];
 private isApplyingDelta: boolean = false;

 constructor(
   public readonly documentId: string,
   public storageFormat: string = 'OCAF-GovernedBinary-v1',
   private readonly undoLimit: number = 100
 ){
   this.root = new OCAFLabel(0, null, this);
 }

  public openCommand(commandName: string): number {
    if (this.activeTransaction !== null) {
      throw new Error(
        `Cannot open command "${commandName}": Transaction #${this.activeTransaction.id}
("${this.activeTransaction.name}") is already open.`
      );
    }
    const id = this.nextTransactionId++;
    this.activeTransaction = { id, name: commandName, deltas: [] };
    return id;
  }

 public commitCommand(): TransactionFrame {
    if (this.activeTransaction === null) {
      throw new Error('Cannot commit command: No active transaction is open.');
    }
    const frame: TransactionFrame = {
      transactionId: this.activeTransaction.id,
      commandName: this.activeTransaction.name,
      timestampMs: Date.now(),
      deltas: [...this.activeTransaction.deltas],
    };
    this.activeTransaction = null;
    if (frame.deltas.length > 0) {
      this.undoStack.push(frame);
      if (this.undoStack.length > this.undoLimit) {
        this.undoStack.shift();
      }
      this.redoStack.length = 0;
    }
    return frame;
}

public abortCommand(): void {
  if (this.activeTransaction === null) {
    throw new Error('Cannot abort command: No active transaction is open.');
  }
  const deltasToRevert = [...this.activeTransaction.deltas].reverse();
  this.activeTransaction = null;
  this.isApplyingDelta = true;
  try {
    for (const delta of deltasToRevert) {
      const targetLabel = this.root.resolveByEntry(delta.labelEntry, true)!;
      targetLabel.restoreAttributeDirect(delta.guid, delta.beforeState);
    }
  } finally {
    this.isApplyingDelta = false;
  }
}
```
