# G01 technical contract

The signature message is the ASCII domain `OCAF-G01-OPERATOR-RECEIPT-v1\0` followed by the compact JSON serialization of `ReceiptPayload { version, store_id, receipt }`. The receipt includes the claimed stage, G01 identity, source commit, test command, exact `PASS` result, `sha256:` digest, unique receipt ID, and declared limits. The store ID prevents a receipt from being replayed into a different initialized store. The operator public key is pinned when the store is created. The private key is read only for the explicit `operator-sign` CLI command and is not copied into the store.

`prepare` hashes the artifact supplied by the caller. `operator-sign` hashes it again, checks the pinned key and current claim, and signs the payload. `handoff` verifies the signature, streams the artifact into a new file while hashing, and commits the event only when those bytes match the signed digest. The artifact limit is 64 MiB. Later reads rehash stored artifacts and fail if a copy is missing or altered. A failed handoff leaves the claim open. An orphan temporary artifact after an interrupted operation does not advance the journal.

This is local integrity and ordering, not a proof that the reported source commit, test command, or test result actually occurred. An operator must inspect that external evidence before signing. The store directory itself is a local trust boundary: an attacker who can rewrite the journal and operator key may forge a new store. Use file ownership and backups appropriate to the host. The journal is not a consensus log.
